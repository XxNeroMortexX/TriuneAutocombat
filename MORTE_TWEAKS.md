# Morte changes after the Triune 3.1 baseline

The published [v3.1-Morte.1](https://github.com/XxNeroMortexX/TriuneAutocombat/releases/tag/v3.1-Morte.1) tag points to commit `3b2ce131a5496eac319a698471f317e1b4ec9265`.
That release uses Gennro's Triune 3.1 Lua code with the separate MQ2WebUpdate integration. The tag is the baseline for subsequent Morte gameplay tweaks; it will not be moved.

Changes after that tag are listed here. Test status is recorded separately from publication so shared testing on main is not mistaken for completed validation.

## Auto AA controls — published for shared testing

- Auto AA: per-ability ignore, target rank, and purchase order; optional all-standard-AA mode. Fireworks and Consume Experience have independent purchase-table rows as well as cap spender choices above the scrolling list. For repeatable AAs, Stop at limits verified purchases during one Triune run (0 means unlimited); ordinary AAs still stop at the selected rank. Fireworks activation can inventory, leave, or delete only the verified item ID 22309 on the cursor. Consume Experience can activate AA 17789 after a verified purchase, with an equipped Power Source and ready AA.
- Validation: the controls and Consume Experience row were checked in game. Lua syntax and isolated purchase-count/limit checks passed. Actual purchases, Fireworks cursor handling, and Consume Experience activation/item XP still need shared in-game testing.
- Restart observation: a native MQ2Lua crash occurred during `/ac restart` while testing. Restoring the original files loaded successfully; stopping Triune, installing the test files, and starting it separately also succeeded. The crash cause is unconfirmed. Use separate `/lua stop triune` and `/lua run triune` commands during this test.

## Auto-Accept tell and guild commands — published after in-game testing

- Auto-Accept adds separate default-off group invite and DZ add tell controls in the Auto-Accept window and Plugins -> Configure. `invite` / `dzadd` and `invite me` / `dzadd me` use the sender; a single named character can be used instead. Guild commands must begin with this bot's exact name (case-insensitive), for example `Mortefreddo dzadd me`. The same checkboxes, permissions, and cooldown apply to both channels. Commands operate through incoming chat events, without chat polling.
- Tell permission is separate from invite-accept permission: whitelisted names (default), same-guild players (tells require a verified spawn in this zone; genuine guild messages also work across zones), or anyone. The existing whitelist editor supplies names; saved spawn IDs do not authorize tells. An authorized sender may request an invite for another character. A shared two-second cooldown limits command dispatch. Known leadership, full-group, and duplicate-group-member conditions are checked; unavailable client fields leave final permission enforcement to the game. DZ commands require a confirmed current expedition; when none exists, the bot privately tells the authorized sender "I'm not in a DZ to invite you." Unreadable DZ state prevents dispatch without asserting that no DZ exists. These checks do not confirm that an invitation succeeded.
- Settings save with the character's existing Triune loadout. Original Auto-Accept behavior and author credits remain intact; modified blocks are marked `Edited By: NeroMorte`.
- Validation: `texlua tests/test_auto_accept_tells.lua` checks parsing, command-injection rejection, disabled toggles, independent sender permissions, guild verification, cooldown, known leadership restrictions, configuration saves, and event cleanup. The user reported the first tell-command version working in game. The extended isolated checks also cover no-argument defaults, addressed guild messages, private no-DZ replies, and cross-channel cooldown. The user reported the updated tell/guild version working in game and approved merging to main. Settings persistence across a full restart has not been separately confirmed.

## Range controls and AA bank — published after slider testing

- Camp Radius, Pull Radius, Search Radius, and Engagement Distance retain their existing positive minimums and Ctrl+click input. Their drag scales start at 10,000 and expand to higher saved or typed values, removing the old gameplay upper caps. Actual spell and weapon reach still governs ranged pulling.
- Auto AA Bank accepts 1 in the slider, saved-settings cleanup, and purchase threshold helper. Existing defaults remain unchanged. Each modified code block is marked `Edited By: NeroMorte`.
- Validation: Lua syntax and isolated checks passed for large typed/saved ranges, native slider drag bounds, existing positive minimums, and bank 1 through load, UI, purchase helper, and command. The user confirmed Ctrl+click accepts higher values and the expanded slider drag ranges work in game. AA Bank persistence across a full restart has not been separately confirmed.

## True Self spell targeting — published after in-game testing

- Restores the old NeroMorte gem-casting fix using both actual spell Beneficial and TargetType metadata. Beneficial Self spells preserve the current selected target even when the configured recipient is self or pet. They do not lock the cast tracker onto that recipient or queue target restoration. Gennro's existing self-heal exception and targeting for other spells remain intact. Changed blocks are marked `Edited By: NeroMorte`.
- Validation: Lua syntax and isolated execution of the actual castGem function passed for hostile/friendly/no current target, self/pet recipients, bard songs, aborted movement casts, targeted buffs, missing metadata, and existing self-heals. The user confirmed this fix worked in game and approved merging to main. AA and clickie dispatch are unchanged.

## Native EverQuest camp map — published after in-game testing

- Adds default-on Show Camp on EQ Map in Control. MQ2Map draws a green X and radius outline at the saved camp, refreshing when camp/radius changes. Triune's own map remains independent. No shaded fill is attempted because maploc exposes an outline only.
- Every Clear Camp control removes the map marker immediately. It remains absent while no camp exists and redraws automatically when Gennro's puller loop or Set Here creates a camp, keeping both maps aligned. Gameplay camp initialization is unchanged. Removes only the marker location rather than clearing all maplocs; does not change MQ2Map filters. Zone/character changes and normal window closure clear the marker. Forced Lua termination may bypass normal cleanup.
- Validation: Lua syntax and isolated marker/radius, clear/automatic camp recreation, MQ2Map reload, missing/invalid camp, and scoped-removal checks passed. Existing Self spell and range/AA-bank checks still pass. The user confirmed the X/circle works in game. Edited blocks are marked Edited By: NeroMorte.

- In-game observation: the initial marker worked, but Clear Camp while feigned followed by standing recreated the gameplay camp without its EQ marker until Pause/START. The explicit redraw-suppression flag caused that mismatch and has been removed; the isolated check reproduces absent camp followed by automatic recreation without START. The user repeated feign → START → Clear Camp → stand, confirmed automatic redraw now works, and approved merging to main.

## Pet camp controls and pet-state buttons — test branch, live validation pending

- Adds opt-in **Pets Pull - Player Stay in Camp** under Puller → Camp → Pet. When enabled, replaces Engagement Distance with Player Assist Radius, measured from camp. Pets fight eligible mobs within Pull Radius; the character assists only at camp or against a directly targeting hostile, using actual ability/weapon range and without chasing. Only camp-return navigation is permitted. With the toggle off, Gennro's normal movement and pet command path remain in use.
- Optional **Pet Pull Back to Camp**, **Mobs per Pull** (1–100), and **Pulling Pet** (Auto or an owned class). Gathering sends individual attack commands to one living pet with confirmed Taunt ON. If every living pet has confirmed Taunt OFF, fall back to all pets. Unknown does not count as OFF. A mid-pull correction recalls/finishes the current batch before adopting the new taunting pet. No qattack queue assumption is used. Preserves the older far-distance pet assist + owner-attack trigger after a target-settle beat. All-pet fighting enables assist for all; single-pet gathering temporarily disables assist/holds on the other classes, releasing them at camp. A tracked owner-attack lease is allowed only beyond melee reach, waits for melee acknowledgement if switching from ranged mode, and ends on target change, recall, confirmation, timeout or a mob approaching melee reach. The player never chases. A tag counts only when that exact selected mob ID appears in a hostile XTarget slot; ToT and attack commands alone do not confirm it. Already tracked/XTarget mobs are excluded. A two-minute confirmation timeout accommodates far-away pets; target settling still has a ten-second timeout. Any hostile XTarget reaching Player Assist Radius ends gathering early. If no next eligible mob exists, briefly recheck and recall the smaller batch. All pets help at camp; a new batch waits for the pull and hostile XTargets to clear, and for the recalled pulling pet to return.
- Adds a shared session-only per-spawn pet-state cache. Yellow text with a pressed-style button marks known ON/OFF/stance values. Startup/new-pet/manual refresh snapshots are deferred until safely idle, wait for a settled matching Pet.ID, and restore the target only if the player has not changed it. Death, replacement, character or zone changes invalidate old flags. Exact observed taunt tells update the cache; ambiguous position tells do not imply Follow/Guard. Commands invalidate affected fields rather than claiming success. Live window readings belong only to their matching pet. **Assist stays unknown** because its pet-stance telemetry has not been verified; missing SpellHold readings also stay unknown. Cached values are last confirmed values, not guaranteed instantaneous server state for every pet.
- Cache/controller lives in `TAC/lua/TAC_support_modules/pet_camp_controller.lua`, shared by GUI and combat. Settings save in the existing character loadout; pet flags are not persisted. Blocks changed in Gennro's core are marked `Edited By: NeroMorte`.
- Validation: Lua syntax, deterministic controller checks, and execution of actual core action/movement gates and button-style balancing pass. Covers safe target restoration, manual target changes, pet identity/loss, unknown versus OFF, taunt event confirmation, single-pet gathering, all-OFF fallback, taunt correction, quota/arrival recall, timeout, direct defense, return gating, target-settle timing, far-pet attack lease expiry/ranged protection, and disabled behavior. Earlier Self casting, range/AA-bank, camp-map, and tell/guild checks still pass. Actual server pet-command/packet timing and combat behavior require the user's in-game test before merge.

- Recall explicitly sends `/attack off` (and disables autofire when active) before pet back/follow, even if the dispatch lease has already cleared. Returning pets must not immediately auto-assist again. Player combat can resume when the camp fight begins.

- Live-test corrections: automatic snapshots use `EverQuest.GameState`, pets-only combat finishes remaining hostile XTargets before acquiring fresh mobs, and count-one pull-back waits for the exact mob ID in XTargets before recalling. Normal Camp Puller also blocks fresh/closer pulls during existing XTarget fights; Hunt blocks fresh scans while filtered XTargets remain, preserving its explicit Ignore Distant XTargets option. Regression checks execute those ordinary paths and the actual snapshot predicate. These corrections still require live validation on the test branch.

- Pet roster/capture correction after live feedback: known summon names and pet archetypes are resolved before GUI slot requests, conflicting old slot guesses are cleared, and only a sole remaining pet/class may be inferred. Ambiguous pets remain unassigned instead of sending the wrong class command. Own NPC-type pets are excluded from the targeted aggro threat check. Short automatic snapshots defer plugin ticks/memorization until target restoration and report capture completion in chat. Routine stance/assist/hold commands and ambiguous position tells invalidate affected fields without queuing repeated target scans. Startup/new-pet/manual captures remain supported. Dead XTarget remnants no longer delay the next non-returning pet fight. The user's direct targeting test confirmed `/target id` updates the matching Pet window on their client. Isolated roster, three-pet snapshot, threat, and dead-XTarget tests pass; live validation remains pending.

- Post-recall combat correction: a returned puller releases the other pets to finish nearby mobs even just outside Player Assist Radius; hostile targeting of an owned pet at camp also allows pet defense. Owner assistance still uses its configured radius/direct-self-threat and real ability ranges. GATHER is not ended by a distant pulling pet being hit. Far incoming mobs are not chased merely because another batch member died. Native EQ camp radius edits redraw from the GUI with drag coalescing and an exact final redraw on edit completion; slider saves occur on release instead of every drag frame. Routine `Issued: #petcmd` chat is now Debug-only; commands and state invalidation remain unchanged. These changes passed isolated returned-pet, count-three, outside-radius, map-redraw and quiet-command regression checks; live validation remains pending.
